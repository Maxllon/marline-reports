# Датасет для бенчмарков Palantir

Документ фиксирует результат первой задачи: выбор и подготовка данных для сравнения конфигураций иерархии тиров Palantir в MarLine. Дата обращения — 25 октября 2026 года.

## 1. Требования

Набор должен:

- содержать много последовательных версий одного проекта с естественной эволюцией;
- позволять воспроизводимо скачать данные и проверить контрольные суммы;
- покрывать исходный код и, на следующем этапе, backup-style данные;
- помещаться в разумный объём и допускать оконные эксперименты;
- иметь понятную лицензию.

## 2. Выбор данных

| Кандидат | Статус | Решение |
|---|---|---|
| Backup-наборы Palantir (DB_Stock, DB_Forex, VSI, VDI и др.) | Не опубликованы; версии синтетические | Недоступны |
| TAR/LNX/WEB/VMA/CHM | Ссылки устарели, условия неясны | Не использовать |
| Linux kernel | Публичный, есть подписанные SHA-256 | Основной набор первого этапа |

Linux выбран как воспроизводимый набор исходного кода. Его ограничение: выигрыш Palantir на Linux мал (около 1.1% E2E), поэтому выводы нельзя переносить на backup-данные без отдельной проверки.

## 3. Состав набора

14 уникальных версий:

`4.19`, `5.4`, `5.10`, `5.15`, `6.1`, `6.2`, `6.3`, `6.4`, `6.5`, `6.6`, `6.6.7`, `6.6.14`, `6.6.21`, `6.6.28`.

Дополнительно добавлена точная копия `6.6.28` с именем `6.6-dup` для проверки обработки дубликатов. Итого 15 записей, 14 уникальных SHA-256.

- Формат: `linux-VERSION.tar.xz`.
- URL: `https://cdn.kernel.org/pub/linux/kernel/v{4,5,6}.x/linux-VERSION.tar.xz`.
- Суммарный размер: `1 836 352 340` байт (~1.84 ГБ).
- Контрольные суммы: сверены с `sha256sums.asc` с kernel.org; все 14 совпали.
- Лицензия: GPL-2.0.

## 4. Схема экспериментов

Параметры, фиксированные между конфигурациями:

- CDC: `min=8192`, `avg=32768`, `max=65536`;
- seed: `0`;
- sampling rate: `1/128` (`sampling_rate=7`);
- число исходных признаков: `12`;
- baseline: Odess;
- delta-кодер: Gdelta;
- Palantir по умолчанию: `tier_list=4-3-2`.

Режим 1. 14 окон по две соседние версии: `4.19|5.4`, `5.4|5.10`, …, `6.6.21|6.6.28`, `6.6.28|6.6-dup`. Каждое окно — полные деревья, около 1.6 ГБ исходных данных. Этот режим ближе к версионному backup-сценарию и отдельно проверяет exact duplicate.

Режим 2. Единый срез по 15 версиям (включая duplicate) с ограничением размера; около 2.69 ГБ исходных данных. Нужен для проверки масштабирования и воспроизводимости при меньшем числе прогонов.

Метрики: E2E-коэффициент, delta gain, DCC, throughput кодирования и декодирования, размер метаданных, число ложных срабатываний. Для каждой конфигурации выполняются повторные прогоны и считается среднее и среднеквадратическое отклонение.

## 5. Артефакты и воспроизведение

- `materials/kernels/manifest.csv` — версии, роли, URL, SHA-256, размеры, лицензия.
- `materials/kernels/SHA256SUMS` — контрольные суммы для `sha256sum -c`.
- `scripts/fetch_kernel_dataset.sh` — `--check`, `--download`, `--extract`, `--all`.
- Данные по умолчанию: `materials/kernels/data/{tarballs,src}`; каталог исключён из git.

Проверка манифеста и доступности файлов:

```bash
bash scripts/fetch_kernel_dataset.sh --check
```

Полная загрузка и распаковка:

```bash
bash scripts/fetch_kernel_dataset.sh --all
```

Скрипт создаёт `linux-6.6-dup` как копию `linux-6.6.28`; duplicate не скачивается повторно.

## 6. Ограничения

- Backup-style данные пока не включены; это следующий этап.
- Полная распаковка всех версий требует существенно больше диска, чем сжатый набор; для экспериментов используется срез.
- ChunkFS работает в памяти, поэтому размер окна и параллелизм нужно ограничивать.
- Linux — только один класс данных; рекомендации по иерархии тиров требуют проверки на backup-наборе.
